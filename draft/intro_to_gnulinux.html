Unix & The Birth of The GNU Project (1983)

The Free Software Vision
📜

1969–1970s: The Unix Revolution · AT&T Bell Labs

Ken Thompson and Dennis Ritchie created Unix: elegant, multi-tasking, and modular. However, Unix soon became closed-source, proprietary, and heavily locked behind corporate licenses.

💡

1983: Richard Stallman & The GNU Project

At MIT, Richard Stallman (RMS) believed software should be free for all humanity to learn and collaborate. He launched the GNU Project (a recursive acronym: "GNU's Not Unix!") to build an entirely free, open-source Unix-compatible operating system.

Freedom 0: Run Freedom 1: Study code Freedom 2: Redistribute Freedom 3: Modify & Improve
🧰

What GNU Built (The Userland)

By the early 1990s, the GNU Project had built almost the complete operating system:

  • GCC: The GNU C Compiler (compiles software)
  • Bash: The Bourne Again Shell (user terminal)
  • Coreutils: Essential commands (ls, cp, rm)
  • Emacs: The legendary extensible text editor
🧩 The Missing Piece: GNU had built the steering wheel, engine parts, and seats, but was missing a working, stable Kernel (the GNU Hurd kernel project was delayed).

Linus Torvalds & The Birth of Linux (1991)

The Missing Kernel
Usenet Post · comp.os.minix · August 25, 1991
From: Linus Benedict Torvalds (torvalds@kruuna.helsinki.fi) Subject: What would you like to see most in minix? "Hello everybody out there using minix - I'm doing a (free) operating system (just a hobby, won't be big and professional like gnu) for 386(486) AT clones. This has been brewing since April, and is starting to get ready... Any suggestions are welcome, but I won't promise I'll implement them :-)"
💡 Why "GNU/Linux"? The Linux Kernel alone is just an engine; it cannot interact with humans without a shell and userland tools. Combining GNU tools + Linux Kernel created the complete operating system!
🤝

The Marriage of GNU and Linux

Linus released his kernel under GNU's GPL (General Public License). Developers worldwide realized that combining Linus's kernel with GNU's software tools formed a complete, fully functioning, 100% free operating system!

1991
Linux Kernel
Linus writes the initial kernel on an Intel 386 PC.
1993
Debian Born
Ian Murdock creates Debian to package GNU/Linux.
🚀 Open Source Triumph: Thousands of volunteer programmers around the world joined to fix bugs, write drivers, and refine the system, creating a software revolution.

What is a Linux Distribution ("Distro")?

A "Distro" is a complete operating system built from the Linux Kernel + GNU Coreutils + a Package Manager (apt, dnf, pacman) + Desktop & Default Configurations. Each distro tailors the environment to specific goals!

The Operating System Stack & Syscalls

Privilege Separation
🛡️

Strict Privilege Isolation · Ring 0 vs. Ring 3

Hardware operations are restricted to the kernel to prevent application bugs from corrupting physical memory.

🧠

The Linux KernelRing 0 · Privileged

Directly manages physical hardware:

  • CPU scheduling & thread preemption
  • Virtual memory management & paging
  • Hardware device drivers & network queues
📦

User SpaceRing 3 · Unprivileged

Where applications execute safely:

  • User processes (Web servers, Python, Node.js)
  • System daemons (systemd, sshd, cron)
  • Standard C runtime library (glibc)

The Core Philosophy: "Everything is a File"

Unified Abstraction
🌐

A Universal Interface · Everything is Accessible via File Descriptors

Instead of needing different APIs for disks, screens, network cards, and memory, Linux unifies everything into one universal, easy-to-read file paradigm.

📄

1. Regular Files & Folders

Text files, code, and configurations stored on persistent disk blocks.

/etc/hosts /var/log/syslog ~/.bashrc
💽

2. Hardware Devices (/dev)

Hard disks, keyboards, and USB ports represented as files. Reading from them reads hardware signals!

/dev/sda (Disk) /dev/null (Trash can) /dev/urandom
⚡

3. Kernel Virtual State (/proc)

Files created in memory on-the-fly by the kernel. Read them with cat to inspect CPU and RAM state live!

/proc/cpuinfo /proc/meminfo /proc/loadavg
🔀

4. Pipes & Network Sockets

Programs send data to each other and across the internet using standard read() and write() file operations.

Standard Streams (0, 1, 2) UNIX Domain Sockets

Terminal vs. Shell & CLI Ergonomics

Command Line Mechanics
🖥️

Terminal Emulator vs. Shell Interpreter

The Terminal: The window (GNOME Terminal, Kitty) that captures keystrokes and draws characters.

The Shell: The smart program (Bash, Zsh) that interprets the commands you type, checks syntax, and executes programs.

📞 Telephone Analogy: The Terminal is the physical telephone handset (microphone & speaker). The Shell is the helpful human operator on the other end listening to your request and making connections.
⚡

Essential Beginner Muscle Memory

  • Tab Completion: Never type full names! Press Tab to auto-complete file names and avoid typos.
  • History: Press ↑ and ↓ to recall previous commands, or Ctrl + R to search history.
  • Manuals: Run man <command> to read the official manual (press q to quit).
🛑

Emergency Escape Hatches

Ctrl + C ➔ SIGINT: Stop runaway program immediately Ctrl + Z ➔ SIGTSTP: Pause task to background

Stuck in a command? Don't panic: hit Ctrl + C!

02 · Filesystem

Filesystem Hierarchy Standard (FHS)

The Inverted Tree Structure
🌱

/ & /rootRoot Directories

/ is the single ancestor of the entire system. /root is the isolated home directory for the superuser.

⚙️

/etcConfiguration

System-wide, host-specific plain text configuration files (networking, daemon configs, user definitions).

🚀

/bin & /sbinSystem Executables

/bin holds essential user binaries (ls, cp). /sbin holds system administrator binaries (fdisk, ip).

🏠

/home & /usrUsers & Programs

/home/username stores user personal data. /usr contains user software, libraries, and shareable resources.

📊

/var & /tmpVariable & Ephemeral

/var stores changing data like persistent logs (/var/log) and spools. /tmp holds temporary files wiped on reboot.

🔌

/boot & /libBootloader & Libraries

/boot contains the Linux kernel (vmlinuz) and GRUB. /lib holds shared C libraries (libc.so) and kernel modules.

Essential System Configuration Files

Critical System Files
File Path Domain Description & Operational Significance
/etc/passwd User Accounts Defines local user accounts, UIDs, GIDs, home paths, and default login shells.
/etc/shadow Security Hashes Stores salted cryptographic password hashes. Restricted strictly to root (mode 640).
/etc/group User Groups Defines local system groups and secondary memberships (e.g., adding users to sudo, docker).
/etc/sudoers Privilege Rules Controls administrative privilege delegation for sudo. Safely edited via visudo.
/etc/fstab Storage Mounts Filesystem table defining disk partitions, UUIDs, mount points, and automated boot options.
/etc/hosts Static DNS Static table mapping IP addresses to hostnames prior to external DNS queries.
/etc/resolv.conf DNS Resolution Configures upstream DNS nameservers (e.g., nameserver 1.1.1.1) used for domain name lookups.
/etc/os-release Distro Metadata Standard OS identification file (distro name, version ID, codename) checked via cat /etc/os-release.
/etc/crontab Task Scheduling System-wide automated job table defining periodic commands executed by the cron daemon.
~/.bashrc User Environment Executed for interactive bash shells. Configures personal aliases, prompt style, and custom PATH.
~/.ssh/authorized_keys SSH Remote Auth Stores authorized public SSH keys enabling secure, passwordless remote server logins.
/var/log/syslog Audit Trail Central operating system log file recording general system activity, services, and kernel events.

🔒 Security Best Practice: visudo

Never edit /etc/sudoers directly with a standard text editor. Always use sudo visudo, which locks the file against concurrent write collisions and performs strict syntax checks prior to saving.

02 · Filesystem

Virtual Filesystems: /proc & /dev

Kernel State & Devices
🧠

/proc · Virtual Kernel State

/proc does not exist on disk! It is a pseudo-filesystem generated dynamically by the Linux kernel in RAM.

  • /proc/cpuinfo ➔ CPU architecture, cores, and clock frequencies
  • /proc/meminfo ➔ Real-time physical RAM and swap telemetry
  • /proc/loadavg ➔ 1, 5, and 15 minute system load averages
  • /proc/[PID]/ ➔ Metrics and file descriptors for any running process
guigo@linux:~$ cat /proc/loadavg 0.24 0.18 0.12 1/482 18920
🔌

/dev · Hardware & Pseudo-Devices

Represents physical hardware components and special kernel character/block streams:

  • /dev/sda, /dev/nvme0n1 ➔ Physical storage disk blocks
  • /dev/null ➔ Discards all data written to it (black hole sink)
  • /dev/zero ➔ Provides an endless stream of null bytes
  • /dev/urandom ➔ Fast, non-blocking cryptographic random data
# Benchmarking or generating empty file with zero bytes: dd if=/dev/zero of=swapfile bs=1M count=1024

File & Directory Operations

Creating, Copying & Removing
📁

mkdir -p · Directory Trees

Creates nested directory paths in a single command without failing if intermediate parent folders do not exist yet.

Creates an empty file instantly or updates access and modification timestamps without altering existing file data.

03 · Navigation

Searching the Filesystem: find vs. locate

Discovery Utilities
🔍

find · Real-Time Traversal

Crawls directory trees live to match files based on names, modification times, sizes, or types:

# Find .log files larger than 50MB modified in 24h: find /var/log -type f -name "*.log" -size +50M -mtime -1 # Find and delete temp files safely: find /tmp -type f -name "*.tmp" -delete

🎯 Precision Search

Because find queries filesystem metadata live, results are 100% up-to-date.

⚡

locate · Indexed Database Lookup

Queries a pre-indexed system database for near-instant path lookups across massive multi-terabyte drives:

# Near-instant path search: locate nginx.conf # If file was just created, update database manually: sudo updatedb

⏱️ Speed vs. Freshness

locate is orders of magnitude faster than find, but depends on the cron-scheduled updatedb cache.

Software Package Management & sudo

apt & Least Privilege
📦

The apt Lifecycle · Debian & Ubuntu Repositories

Package managers automatically resolve dependencies, verify cryptographic signatures, and install updates.

Standard apt Workflow
# 1. Refresh local repository metadata mirrors sudo apt update # 2. Upgrade all installed packages to latest security releases sudo apt upgrade -y # 3. Install packages and dependencies sudo apt install -y curl htop git build-essential # 4. Remove obsolete orphaned dependencies sudo apt autoremove -y
🛡️

Understanding sudo & Least Privilege

sudo (SuperUser DO): Runs commands with temporary administrative permissions.

  • Avoid Root Shells: Never run as permanent root (sudo -i). Executing commands with sudo minimizes the risk of accidental system damage.
  • Audit Logging: Every sudo execution is recorded with timestamps in /var/log/auth.log for auditing.
🔄

Other Linux Distributions

While commands differ, core package principles remain identical:

Ubuntu/Debian: apt RHEL/Fedora: dnf Arch Linux: pacman

Pipes & Text Filters
Production Telemetry Pipeline: Top 5 Offending IPs Generating 404 Errors 6 STAGES · STDOUT [1] ➔ STDIN [0] PIPES

1 grep
Filter Errors

Scans access log and filters lines by pattern match.

" 404 " Space-padded: matches HTTP 404 status codes only, ignoring port numbers (:4040) or byte counts.
STDOUT [1] ➔ 192.168.1.50 - [..] "GET /admin" 404 182
2 awk
Extract Column

Positional text parser: splits incoming lines by whitespace.

'{print $1}' Prints Field 1 (remote client IP), discarding timestamps, HTTP verbs, paths, and user-agents.
STDOUT [1] ➔ 192.168.1.50 (isolated bare IP stream)
3 sort
Group Adjacent

Alphabetically orders IP stream to group duplicates.

(default) Vital prerequisite: uniq only detects adjacent duplicates! Scattered duplicates are missed if unsorted.
STDOUT [1] ➔ 192.168.1.50 · 192.168.1.50 (clustered)
4 uniq
Count Frequency

Collapses repeated adjacent lines into unique occurrences.

-c (--count) Prefixes each unique line with its repetition count, creating a [count] [ip] histogram table.
STDOUT [1] ➔ 1420 192.168.1.50  |  831 10.0.0.15
5 sort
Rank Descending

Reorders statistical counts from worst offender to lowest.

-n Numeric (evaluates 100 > 20, not ASCII); -r Reverse order (descending: highest hits at top).
STDOUT [1] ➔ 1420 192.168.1.50 (Rank #1) · 831 ...
6 head
Slice Top 5

Extracts head portion of stream and terminates pipe.

-n 5 Restricts output to top 5 lines, discarding the rest of the stream for immediate security or firewall action.

System & Process Management

Monitoring & Signals
📸

Inspecting Workloads: ps aux

Captures a point-in-time snapshot of active processes:

  • a: Shows processes across all users
  • u: Formats with user attribution, %CPU, and %MEM
  • x: Includes background daemons not attached to a TTY
📈

Real-Time Monitors: top & htop

top: Built-in monitor displaying CPU load, 1/5/15 min load averages, RAM/swap usage.

htop: Enhanced interactive manager with colored core meters, tree views, and search.

🛑

Controlling Processes & Signals

1. Locate PID: pgrep -l nginx

2. Graceful Shutdown (Default): kill <PID>
Sends SIGTERM (Signal 15). Allows the application to save state, close sockets, and remove lock files.

3. Forceful Termination: kill -9 <PID>
Sends SIGKILL (Signal 9). Handled directly by kernel; bypasses application cleanups. Use only if completely frozen!

🔄

Job Control Mechanics

Launch in background: python3 server.py &

List background tasks: jobs

Bring to foreground: fg %1 | Resume in background: bg %1

Remote Administration & Shell Scripting

SSH & Bash Automation
🔐

Remote Administration: ssh

The industry-standard encrypted shell protocol:

# Standard connection ssh guigo@remote-server.com # Connect via non-standard port and private key ssh -i ~/.ssh/id_ed25519 -p 2222 guigo@remote-server.com
📦

Archiving & Compression: tar

Package directory trees into compressed .tar.gz:

# Create compressed archive: c=create, v=verbose, z=gzip, f=file tar -cvzf site_backup.tar.gz /var/www/html # Extract archive to destination folder (-C) tar -xvzf site_backup.tar.gz -C /opt/restore
Production Bash Script: backup.sh
#!/bin/bash # Strict mode: fail on error, unset vars, or pipe break set -euo pipefail BACKUP_SRC="/var/www/html" BACKUP_DEST="/backup" DATE=$(date +%Y%m%d_%H%M%S) ARCHIVE="web_backup_${DATE}.tar.gz" echo "=== [$(date)] Starting System Backup ===" mkdir -p "${BACKUP_DEST}" tar -cvzf "${BACKUP_DEST}/${ARCHIVE}" "${BACKUP_SRC}" echo "=== Backup saved: ${BACKUP_DEST}/${ARCHIVE} ==="
🚀 Deploying: Run chmod +x backup.sh to grant execution rights, then execute ./backup.sh or schedule via crontab -e.

🆔

Host & Distribution Identification

Every Linux distribution exposes standardized metadata files:

  • cat /etc/os-release · Official distribution name, version, and codename (Ubuntu, Debian, Fedora, Arch).
  • hostnamectl · Modern unified systemd status: chassis, OS, kernel, and machine architecture.
  • whoami & id · Current user login name, UID, and group memberships.
🛂 Passport Analogy: Just like an international passport, uname -a and /etc/os-release prove who the machine is, which country (distro) issued it, and what language (kernel ABI) it speaks!
Terminal: Hostname, Kernel & Uptime
# Check system kernel release & architecture $ uname -a Linux srv01 6.1.0-21-amd64 #1 SMP x86_64 GNU/Linux # Print kernel release only (-r is vital for drivers) $ uname -r 6.1.0-21-amd64 # How long has this machine been running? $ uptime -p up 14 days, 3 hours, 22 minutes # System load average (1, 5, 15 minute averages) $ uptime 14:22:05 up 14 days, load average: 0.12, 0.08, 0.05
💡 Why Kernel Version Matters: Compiling hardware drivers (like NVIDIA or Wi-Fi) requires the exact matching headers: linux-headers-$(uname -r).

CPU Architecture & Processor Telemetry

Compute Topologies
⚡

The Computational Core · Sockets, Cores & Hyper-Threading

CPUs execute all instructions. Probing the processor reveals core hierarchies, clock speeds, cache tiers, and virtualization flags.

🧠

CPU Topology Breakdown (lscpu)

Understanding processor geometry:

  • Architecture: x86_64 (Intel/AMD 64-bit) vs aarch64 (ARM64).
  • Socket(s): Physical CPU chips seated on the motherboard.
  • Core(s) per socket: Physical silicon computation engines.
  • Thread(s) per core: SMT / Hyper-Threading (if 2, each physical core handles 2 logical execution streams).
🛡️

Virtualization Support (VT-x / AMD-V)

Can this machine run Docker or Virtual Machines at hardware speed?

grep -E "vmx|svm" /proc/cpuinfo vmx: Intel VT-x svm: AMD-V
Terminal: lscpu Overview
$ lscpu Architecture: x86_64 CPU(s): 16 Thread(s) per core: 2 Core(s) per socket: 8 Socket(s): 1 Vendor ID: AuthenticAMD Model name: AMD Ryzen 7 7800X3D 8-Core CPU max MHz: 5050.0000 Virtualization: AMD-V # Watch live CPU clock scaling across all cores $ watch -n 1 "grep 'cpu MHz' /proc/cpuinfo"

🏎️ Cache Hierarchy (L1 / L2 / L3)

L1 is ultra-fast per-core memory (~1ns), L2 is medium (~3ns), L3 is shared across all cores (~12ns). High L3 cache prevents costly trips to physical RAM.

Memory (RAM): The "Available vs. Free" Golden Rule

Memory Telemetry
🧠

Demystifying Linux Memory · "Unused RAM is Wasted RAM!"

Beginners panic when they see near-zero "free" memory. Don't worry — Linux aggressively uses spare RAM for lightning-fast disk caching!

📊

The Columns of free -h

  • total: Total installed physical RAM minus kernel reserved space.
  • used: Memory actively allocated by your running applications.
  • free: Completely untouched, idle RAM (wasted potential!).
  • buff/cache: Disk blocks cached in RAM to make file access instant.
  • available: The metric that matters! RAM immediately reclaimable for new applications without swapping.
🌟 The Golden Rule: Always monitor available, NEVER free! If available is healthy, your system has plenty of breathing room. The kernel evicts cache in nanoseconds when needed.
Terminal: free -h Output
$ free -h total used free shared buff/cache available Mem: 31Gi 8.2Gi 1.1Gi 420Mi 22Gi 22Gi Swap: 4.0Gi 0B 4.0Gi # Monitor live memory pressure & swap-in/out $ vmstat 1 procs -----------memory---------- ---swap-- r b swpd free buff cache si so 0 0 0 1153200 452100 226830 0 0
🔍

Physical DIMMs: sudo dmidecode -t memory

Inspect physical motherboard slots, DDR4/DDR5 generation, clock speed (e.g. 5600 MT/s), and manufacturer without opening the computer chassis.

Storage & Block Devices: Disks, Partitions & Usage

Block Devices & Space Triage
💾

Physical Drives to Filesystems · NVMe, SATA & Disk Space Triage

Linux organizes storage into block devices (/dev/sd*, /dev/nvme*), partitions, and mount points. Learn how to map drives and locate disk hogs.

🗄️

1. Block Hierarchy: lsblk -f

Displays all storage devices, partition schemes, and filesystems:

  • nvme0n1 · NVMe SSD (bus 0, namespace 1)
  •   ├─ nvme0n1p1 · EFI System Partition (/boot/efi)
  •   └─ nvme0n1p2 · Linux Root Filesystem (/, ext4)
  • sda · SATA Hard Drive or connected USB flash drive
⚖️

2. df vs. du: Knowing the Difference

  • df -h (Disk Free): Filesystem level. Answers: "How full is my disk partition right now?"
  • du -sh * (Disk Usage): Directory level. Answers: "Which specific folder is eating all my storage?"
Terminal: df -h & Space Triage Recipe
$ df -h / Filesystem Size Used Avail Use% Mounted on /dev/nvme0n1p2 468G 120G 325G 27% / # Find the top 5 largest directory hogs in /var $ sudo du -h --max-depth=1 /var | sort -hr | head -n 5 14G /var/lib/docker 4.2G /var/log 1.8G /var/cache 620M /var/lib 120M /var/backups

🛡️ Drive Health Telemetry: smartctl

Run sudo smartctl -H /dev/nvme0n1 to audit drive health, wear level percentage, and reallocated bad sectors before hardware failure occurs!

Network Interfaces, IP Addressing & Sockets

The Network Stack
🌐

Connecting to the World · Interfaces, IP Addresses & Open Ports

Discover which network cards are active, determine your local and public IP addresses, inspect default gateways, and see which background services are listening.

🔌

Network Interface Anatomy (ip a)

  • lo (Loopback): 127.0.0.1 · Internal virtual interface used for the machine to talk to local services.
  • eth0 / enp3s0: Wired Ethernet network interface.
  • wlan0 / wlp2s0: Wireless Wi-Fi adapter.
  • inet: IPv4 address assigned to the card (e.g. 192.168.1.105/24).
📬 Apartment Analogy: Your Private IP (192.168.1.15) is your apartment door number; your Public IP (203.0.113.42) is the building's street address; Port numbers (:80, :22) are specific mailboxes!
Terminal: IP, Gateway & Listening Sockets
# View brief status of network interfaces $ ip -br a lo UNKNOWN 127.0.0.1/8 ::1/128 enp3s0 UP 192.168.1.105/24 fe80::... # Check Default Gateway (Router IP) $ ip route | grep default default via 192.168.1.1 dev enp3s0 proto dhcp # What public IP does the internet see? $ curl -s ifconfig.me 203.0.113.42 # Audit active listening ports (TCP/UDP, PIDs) $ sudo ss -tulpn tcp LISTEN 0 128 0.0.0.0:22 users:(("sshd",pid=842)) tcp LISTEN 0 511 0.0.0.0:80 users:(("nginx",pid=1120))
⚡ Quick Diagnostic: ping -c 4 8.8.8.8 tests your gateway & routing; ping -c 4 google.com tests whether DNS domain resolution works!
