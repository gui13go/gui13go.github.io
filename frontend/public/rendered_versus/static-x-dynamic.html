Static x Dynamic

Type Systems
Corner A

Static Typing (Compile Time) Compile-Time Type Checking

Static Typing (Rust, Go, TypeScript, C++, Java). Variable types are checked and enforced at compile time. Catches type mismatches, null dereferences, and interface errors before code ever runs in production.

VS
Corner B

Dynamic Typing (Runtime) Runtime Type Checking

Dynamic Typing (Python, JavaScript, Ruby, PHP). Variable types are associated with runtime values rather than variable declarations. Code is written rapidly with high flexibility, with type errors manifesting at runtime.

Key Differences & Divergences

  • Error Detection: Caught early during compilation (Static) VS Caught during runtime execution or via automated unit test suites (Dynamic).
  • Refactoring: Fearless large-scale codebase refactoring with compiler guarantees and IDE auto-complete VS Requires high unit test coverage to ensure refactors do not break runtime types.
  • Development Speed: Upfront type ceremony and compiler wrestling VS Instant prototyping and rapid iterative scripting.
  • Industry Shift: The massive rise of TypeScript over vanilla JavaScript and Python type hints (PEP 484) demonstrated modern industry demand for static type safety.

Common Ground

Type system philosophies governing how programming languages verify data safety and program correctness.
