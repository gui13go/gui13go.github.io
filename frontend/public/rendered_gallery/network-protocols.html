WPA3

Pioneered by: Wi-Fi Alliance

Wi-Fi Protected Access 3 (WPA3) is the next generation of Wi-Fi security. It adds new features to simplify Wi-Fi security, enable more robust authentication, and deliver increased cryptographic strength for highly sensitive data markets.

Real-World Applications:
  • Public Wi-Fi Protection: Enhanced data privacy in open networks (like airports or cafes) through individualized data encryption which protects traffic even if the network isn't password-protected.
  • Brute-Force Attack Resistance: The SAE (Simultaneous Authentication of Equals) protocol provides much better protection against offline dictionary attacks compared to WPA2.

QUIC

Pioneered by: Jim Roskind (Google)

Quick UDP Internet Connections (QUIC) is a general-purpose transport layer network protocol initially designed by Google. It was designed to provide security equivalent to TLS/SSL, along with reduced connection and transport latency, and bandwidth estimation in each direction to avoid congestion.

Real-World Applications:
  • High-Speed Web Browsing: Used by modern browsers to speed up connections to services, significantly reducing the time it takes to establish a secure connection compared to TCP+TLS.
  • Stream Multiplexing: Eliminating 'head-of-line blocking' by allowing multiple data streams to arrive independently, which is particularly beneficial on lossy or unstable mobile networks.

DCCP

Pioneered by: IETF

The Datagram Congestion Control Protocol (DCCP) is a message-oriented transport layer protocol. It is designed to provide unreliable packet flows with easily configured congestion control mechanisms, useful for streaming media.

Real-World Applications:
  • Streaming Media with Congestion Control: Designed for applications like internet radio or game streaming that want the timeline of UDP but are 'network good citizens' that react to congestion signals (ECN) to avoid collapsing the network.

WPA2

Pioneered by: Wi-Fi Alliance

Wi-Fi Protected Access 2 (WPA2) is a security protocol and certification program developed by the Wi-Fi Alliance to secure wireless computer networks. It significantly improved upon its predecessors by introducing the Counter Mode with Cipher Block Chaining Message Authentication Code Protocol (CCMP) based on AES.

Real-World Applications:
  • Home Wi-Fi Security: The industry standard for decades in securing home wireless routers, preventing unauthorized neighbors or attackers from eavesdropping on traffic.
  • Enterprise Mobility: Providing secure, encrypted wireless access for corporate laptops and mobile devices in an office environment.

IGMPv3

Pioneered by: Cain, Deering, et al.

Version 3 of the Internet Group Management Protocol (IGMP) adds support for source-specific multicast, allowing a receiver to explicitly signal interest in traffic from a specific source address, improving bandwidth utilization and security.

Real-World Applications:
  • Source-Specific Multicast (SSM): Allows a client to subscribe to a specific multicast channel from a *specific* source IP. This is crucial for modern IPTV networks to prevent unauthorized streams and optimize routing.

SFTP

Pioneered by: IETF (Secsh Working Group)

SSH File Transfer Protocol (SFTP) is a secure network protocol that provides file access, file transfer, and file management over any reliable data stream. It was designed by the IETF as an extension of SSH to provide secure file transfer capability. Unlike the legacy FTP protocol, SFTP encrypts both commands and data, preventing passwords and sensitive information from being transmitted in the clear over the network.

Real-World Applications:
  • Secure Content Deployment: Replacing legacy FTP for uploading sensitive web assets, configuration files, and code to production servers without risking credential theft.
  • Automated Data Backups: Facilitating secure, scriptable transfers of database dumps and log files between servers over public networks using SSH key authentication.
#File Transfer #Security #Encryption #SSH #Application Layer

TLS/SSL

Pioneered by: IETF / Netscape

Transport Layer Security (TLS), the successor to Secure Sockets Layer (SSL), is a cryptographic protocol designed to provide communications security over a computer network. It is widely known for securing web traffic (HTTPs).

Real-World Applications:
  • Securing Web Traffic: It is the 'S' in HTTPS. It encrypts the connection between your browser and the web server, ensuring no one can spy on your data.
  • Email Security: Used to encrypt connections between mail servers (STARTTLS) to prevent emails from being read in transit.
#Security #Encryption #Transport/Application #Web

MQTT

Pioneered by: Andy Stanford-Clark (IBM), Arlen Nipper (Arcom)

Message Queuing Telemetry Transport (MQTT) is a lightweight, publish-subscribe network protocol that transports messages between devices. It is specifically designed for constrained devices and low-bandwidth, high-latency or unreliable networks.

Real-World Applications:
  • Smart Home Automation: Efficiently communicating state changes and commands between low-power sensors (like door sensors or thermometers) and a central home automation hub.
  • Industrial Remote Monitoring: Transmitting critical telemetry data from remote field equipment over expensive or unstable satellite and cellular links.

RDP

Pioneered by: Microsoft

Remote Desktop Protocol (RDP) is a proprietary protocol developed by Microsoft which provides a user with a graphical interface to connect to another computer over a network connection. The user employs RDP client software for this purpose, while the other computer must run RDP server software.

Real-World Applications:
  • Remote Work: Allowing employees to securely log into and control their office workstations from home as if they were sitting right in front of them.
  • System Administration: Enabling IT professionals to troubleshoot and manage servers or user computers remotely without needing physical access.

LDAPS

Pioneered by: IETF

Lightweight Directory Access Protocol over SSL/TLS (LDAPS) is a secure version of LDAP. It provides the same directory access services but adds a layer of encryption and authentication through SSL/TLS, ensuring that sensitive credentials and directory data are protected while in transit.

Real-World Applications:
  • Secure Corporate Authentication: Protecting user passwords and sensitive identity data when authenticating against Active Directory or other LDAP servers over untrusted networks.
  • Compliance and Data Privacy: Meeting regulatory requirements (like GDPR or HIPAA) by ensuring all person-identifiable information (PII) stored in directories is encrypted during transmission.

RSVP

Real-World Applications:

  • MPLS Traffic Engineering: Often paired with MPLS to create dedicated paths through a service provider's network for specific customer traffic classes.

Real-World Applications:

  • Instant Messaging Presence: Often used in unified communication suites to handle user presence (online/offline/away) and instant messaging sessions.

RTP

Pioneered by: Audio-Video Transport Working Group

The Real-time Transport Protocol (RTP) is a network protocol for delivering audio and video over IP networks. It is used extensively in communication and entertainment systems that involve streaming media.

Real-World Applications:
  • Media Transport: Carries the actual audio and video streams for calls set up by SIP. It includes timestamps and sequence numbers to help the receiver sync sound and video and handle jitter.

IPsec

Pioneered by: IETF IPsec Working Group

Internet Protocol Security (IPsec) is a secure network protocol suite that authenticates and encrypts packets of data to provide secure encrypted communication between two computers over an Internet Protocol network.

Real-World Applications:
  • Virtual Private Networks (VPNs): The industry standard for creating secure, encrypted tunnels between a remote worker and the corporate office, or between two office locations (Site-to-Site).
  • Securing IP Traffic: Can be used to encrypt all IP traffic between two critical servers (e.g., a web server and a database server) within an internal network.

SSH

Pioneered by: Tatu Ylönen

Secure Shell (SSH) is a cryptographic network protocol for operating network services securely over an unsecured network. Its most notable applications are remote login and command-line execution.

Real-World Applications:
  • Remote Server Administration: The standard tool for system administrators to securely log into and manage remote Linux servers and cloud infrastructure.
  • Secure File Transfer (SFTP): Uses the SSH channel to transfer files securely between computers, ensuring both authentication and data encryption.

HTTPS

Pioneered by: Netscape Communications

Hypertext Transfer Protocol Secure (HTTPS) is an extension of the Hypertext Transfer Protocol (HTTP). It is used for secure communication over a computer network, and is widely used on the Internet. In HTTPS, the communication protocol is encrypted using Transport Layer Security (TLS) or, formerly, Secure Sockets Layer (SSL).

Real-World Applications:
  • E-Commerce Transactions: Encrypts credit card numbers and personal information during checkout processes, preventing interception by man-in-the-middle attacks.
  • Secure Authentication: Protects user credentials (usernames and passwords) during login procedures on banking sites, email providers, and social media platforms.

Real-World Applications:

  • Network Management: Allows network administrators to centrally manage and automate the assignment of IP configurations, preventing address conflicts.

Pioneered by: Tim Berners-Lee

  • Web Page Retrieval: The primary protocol for fetching HTML documents and assets from web servers to browsers.

BGP

Pioneered by: Kirk Lougheed, Yakov Rekhter

Border Gateway Protocol (BGP) is the standardized exterior gateway protocol designed to exchange routing and reachability information among autonomous systems (AS) on the Internet. It is the protocol that makes the internet work.

Real-World Applications:
  • Internet Routing: BGP allows different Internet Service Providers (ISPs) to share routing information, determining the most efficient path for your data to travel across the globe.
  • Enterprise Multihoming: Large companies use BGP to connect to multiple ISPs simultaneously for redundancy. If one connection fails, BGP automatically reroutes traffic through the other.

Open Shortest Path First (OSPF) is a link-state routing protocol for Internet Protocol (IP) networks. It uses a link state routing algorithm and falls into the group of interior gateway protocols, operating within a single autonomous system.

Real-World Applications:
  • Large Enterprise & ISP Networks: The standard Interior Gateway Protocol (IGP) for large, multi-vendor networks. It divides the network into 'Areas' to scale efficiently to thousands of routers.
  • Data Center Routing: Used within modern data center fabrics to distribute reachability information between spine and leaf switches.

UDP

Pioneered by: David P. Reed

User Datagram Protocol (UDP) is one of the core members of the Internet protocol suite. It uses a simple connectionless communication model with a minimum of protocol mechanism. UDP provides checksums for data integrity, and port numbers for addressing different functions at the source and destination of the datagram.

Real-World Applications:
  • Real-Time Video Streaming & VoIP: Applications like Zoom or Skype prioritize speed over perfect accuracy. UDP sends packets without waiting for acknowledgments, minimizing latency. A few lost pixels or a millisecond of audio dropout is preferable to the lag caused by TCP retransmissions.
  • Online Gaming: Fast-paced multiplayer games use UDP to update player positions and actions in real-time. The overhead of TCP handshakes and error correction would introduce unacceptable input lag.
  • DNS Queries: Domain Name System lookups typically use UDP because they are small, single request-response transactions where the overhead of establishing a TCP connection would slow down web browsing significantly.
#Connectionless #Fast #Transport Layer #Real-time #Streaming
1974

TCP

Pioneered by: Vint Cerf, Bob Kahn

Transmission Control Protocol (TCP) is one of the main protocols of the Internet protocol suite. It provides reliable, ordered, and error-checked delivery of a stream of bytes between applications running on hosts communicating via an IP network. Major internet applications such as the World Wide Web, email, remote administration, and file transfer rely on TCP.

Real-World Applications:
  • Reliable Web Browsing (HTTP/HTTPS): TCP is the backbone of the World Wide Web. When you load a webpage, TCP ensures that all HTML, CSS, and JavaScript files are received exactly as sent. If packets are lost due to congestion, TCP retransmits them, ensuring the page renders correctly without corruption.
  • Email Delivery (SMTP, IMAP, POP3): Email systems require guaranteed delivery. TCP establishes a connection between mail servers and clients, ensuring that your message structure and attachments remain intact during transit.
  • Secure Shell (SSH) & File Transfers (FTP): For administrative tasks and file management where data integrity is critical, TCP provides the necessary error checking and ordered delivery to prevent corrupted files or commands.
#Reliable #Connection-oriented #Transport Layer #Infrastructure
1971

Real-World Applications:
  • Website Maintenance: Traditionally used by web developers to upload HTML and script files to a web server.
  • Legacy Data Archives: Still widely used in academic and industrial settings for accessing public repositories of large datasets or software distributions.

Telnet

Pioneered by: Postel, Reynolds

Telnet is an application layer protocol used to provide a bidirectional interactive text-oriented communication facility using a virtual terminal connection. It was the standard for remote access before SSH, but because it sends all data (including passwords) in plain text, it is now considered insecure for use over public networks.

Real-World Applications:
  • Configuring Legacy Hardware: Accessing older network switches or industrial equipment that does not support newer, secure protocols like SSH.
  • Service Debugging: Testing connectivity to specific ports on a server (e.g., 'telnet example.com 80') to manually verify if a service is responding.
