Essential Database Internals Quick Guide

Master the fundamental computer science primitives that distinguish world-class storage engines.

B-Tree vs. LSM-Tree

B-Trees (Postgres, SQLite, InnoDB) update pages in-place on disk with O(log N) random read/write lookups. LSM-Trees (RocksDB, Cassandra, ScyllaDB) buffer writes in a sequential in-memory MemTable before flushing immutable SSTables to disk, trading read amplification for virtually unlimited sequential write speed.

Row-Store vs. Columnar

Row stores lay entire tuple attributes consecutively in 8KB disk blocks—ideal for single-row OLTP CRUD mutations. Columnar engines (DuckDB, ClickHouse) store contiguous arrays of single columns, allowing CPU SIMD vector processing to scan millions of values per cycle with extreme compression ratios (ZSTD/Gorilla).

WAL & MVCC

Write-Ahead Logging (WAL) guarantees durability by writing transaction changes to an append-only log before modifying data pages. Multi-Version Concurrency Control (MVCC) tags tuples with creation and expiration transaction IDs, guaranteeing readers never block writers and writers never block readers.

HNSW & Vector Indexing

Hierarchical Navigable Small World (HNSW) graphs construct multi-layer proximity networks reminiscent of skip lists. High-layer traversals jump across wide vector spaces before zooming into fine-grained local neighborhoods, executing k-Nearest Neighbor searches across millions of embeddings in single-digit milliseconds.

Relational / ORDBMS

PostgreSQL

1996
Pioneered by: Michael Stonebraker & PostgreSQL Global Development Group

PostgreSQL is an enterprise-class, open-source object-relational database system with more than 35 years of active development. Known as the 'Linux of Databases', Postgres is famed for rock-solid data integrity, extensibility (foreign data wrappers, custom data types, PostGIS, pgvector), and full ACID compliance. It handles complex analytical queries, transactional workloads, and JSON document structures with equal mastery.

Storage Engine:Heap Files (append-only MVCC) + Buffer Pool
Storage Model:Row-Oriented
Query Interface:SQL (ANSI compliant) + PL/pgSQL
Concurrency:MVCC (Snapshot Isolation & SSI)
ACID & Consistency:Full ACID (Snapshot Isolation, Serializable SSI via SIREAD locks)
P99 Latency Profile:< 1ms OLTP point reads | 5-50ms analytical aggregate
Architectural Highlights & Internals:
  • MVCC Architecture: Multi-Version Concurrency Control prevents read-write blocking by retaining row versions during transactions.
  • Unmatched Extensibility: Pluggable procedural languages, custom index types (B-Tree, Hash, GiST, SP-GiST, GIN, BRIN), and extensions like PostGIS and pgvector.
  • Reliable Write-Ahead Logging (WAL): Guarantees zero data loss with point-in-time recovery (PITR) and synchronous/asynchronous streaming replication.
  • Native Hybrid Semi-Structured Data: Fast binary JSON processing via JSONB with GIN indexing for document queries.

Sweet Spot: System-of-record OLTP, complex relational joins, enterprise apps, hybrid JSON/vector workloads
Superpowers:
  • + Battle-tested rock-solid data integrity with 35+ years of production hardening
  • + World-class extensibility (pgvector, PostGIS, TimescaleDB, Citus, custom data types)
  • + Native rich JSONB support with GIN index queries matching document DB speeds
Architectural Constraints:
  • - Process-per-connection model requires connection poolers (PgBouncer) for >1000 clients
  • - Table bloat requires active VACUUM tuning due to append-only MVCC dead-tuples

Embedded Relational (OLTP)

SQLite

2000
Pioneered by: D. Richard Hipp

SQLite is a C-language library that implements a small, fast, self-contained, high-reliability, full-featured SQL database engine. Unlike client-server databases, SQLite does not run as a standalone background process; instead, it compiles directly into host applications and stores the entire database in a single cross-platform disk file. It is the most widely deployed database engine on Earth, running on billions of smartphones, browsers, IoT devices, and operating systems.

Storage Engine:B-Tree on Flat File / Pager Architecture
Storage Model:Row-Oriented
Query Interface:SQL
Concurrency:Single-Writer / Multiple-Readers (WAL mode)
ACID & Consistency:Full ACID (Atomic commit via rollback journal or Write-Ahead Log)
P99 Latency Profile:< 50 microseconds in-process disk read | ~1 microsecond in-memory
Architectural Highlights & Internals:
  • Zero-Configuration & Serverless: No server process to install, configure, manage, or restart. Simply open a file path and query.
  • Single-File Portability: The entire database (schema, data, tables, indexes) is stored in a single standard cross-platform binary file.
  • WAL Mode Performance: Write-Ahead Logging allows concurrent readers to operate without blocking writes and vice versa.
  • 100% Branch Test Coverage: One of the most rigorously tested software libraries in computing history.
High-Performance WAL Mode & Pragmas

Sweet Spot: Mobile apps (iOS/Android), desktop software, IoT devices, local-first web apps, edge SQLite
Superpowers:
  • + Zero administration, zero background daemon, embeds directly into binary
  • + Extremely small binary footprint (< 1MB) with 100% branch test coverage
  • + Cross-platform single-file container (usable as application file format)
Architectural Constraints:
  • - Single-writer concurrency limit (WAL mode allows concurrent readers, but only 1 writer)
  • - No client-server security model or user permission access controls

  • Zero External Dependencies: Clean C++11 single-file amalgamations that embed anywhere from a Lambda function to a browser tab via WebAssembly.
  • Advanced Analytic SQL: Supports ASOF joins, window functions, regex, recursive CTEs, and automatic query parallelization across CPU cores.

Browser Client-Side NoSQL

IndexedDB

2015
Pioneered by: W3C Web Applications Working Group (Nikunj Mehta et al.)

IndexedDB is a low-level browser API for client-side storage of significant amounts of structured data, including files and blobs. Unlike localStorage (which is synchronous, string-only, and capped at ~5MB), IndexedDB operates asynchronously, provides ACID transactional guarantees, allows indexes for high-performance searches, and can store gigabytes of offline application state right inside Chrome, Firefox, Safari, and Edge.

Storage Engine:Browser Host Native (LevelDB / SQLite under the hood)
Storage Model:Object Store Key-Path
Query Interface:JavaScript Event-Driven Asynchronous API
Concurrency:Transaction-Based (Read-Only / Read-Write locks)
ACID & Consistency:ACID transactional scopes (readwrite and readonly transaction modes)
P99 Latency Profile:1-10ms asynchronous transactional browser disk read/write
Architectural Highlights & Internals:
  • Structured Object Stores: Stores native JavaScript objects, Blobs, ArrayBuffers, and JSON records without serialization overhead.
  • Asynchronous & Non-Blocking: DOM rendering and UI threads are never blocked during intensive disk I/O.
  • Compound Secondary Indexes: Index multiple object properties to enable range queries, cursors, and exact-match searches.
  • Offline-First Web Foundation: Essential architectural backbone for Progressive Web Apps (PWAs), offline caching, and local-first software.

Redis

2009
Pioneered by: Salvatore Sanfilippo (antirez)

Redis (Remote Dictionary Server) is an open-source, in-memory data store used by millions of developers as a cache, message broker, streaming engine, and database. By keeping all primary data in RAM and executing operations on native data structures (Strings, Hashes, Lists, Sets, Sorted Sets, Bitmaps, HyperLogLogs, Geospatial indexes), Redis routinely serves millions of requests per second with sub-millisecond latencies.

Storage Engine:In-Memory Hash Table + SkipLists + Radix Trees
Storage Model:RAM-first In-Memory
Query Interface:Command Protocol (RESP) + Lua Scripts
Concurrency:Single-Threaded Event Loop (Multiplexed I/O)
ACID & Consistency:Transactions via MULTI/EXEC (atomic execution, no rollbacks on logic error)
P99 Latency Profile:< 500 microseconds sub-millisecond P99 in-memory latency
Architectural Highlights & Internals:
  • Sub-Millisecond In-Memory Speed: Direct RAM lookups execute without disk seek penalties, serving P99 latencies under 1 millisecond.
  • Rich Native Data Structures: Manipulate complex arrays, sorted rankings, sets, and geospatial coordinates atomically.
  • Configurable Persistence: Balances speed and durability via point-in-time snapshots (RDB) and append-only write logs (AOF).
  • Pub/Sub & Streams: Real-time message broadcasting, consumer groups, and high-throughput event sourcing pipelines.

Columnar OLAP Data Warehouse

ClickHouse

2016
Pioneered by: Alexey Milovidov & Yandex

ClickHouse is a fast, open-source column-oriented database management system that allows generating analytical data reports in real time using SQL queries. Designed to ingest trillions of rows and petabytes of data, ClickHouse stores columns contiguously on disk with heavy compression, reading only the exact bytes requested by queries and delivering answers up to 100-1000x faster than traditional row-oriented databases.

Storage Engine:MergeTree Engine Family (Sparse Indexes)
Storage Model:Columnar Compressed
Query Interface:SQL (Extended ClickHouse SQL)
Concurrency:Massive Parallel Processing (MPP) / Vectorized
ACID & Consistency:Eventual consistency across shards; atomic partition and block inserts
P99 Latency Profile:10-50ms analytical queries across billions of rows
Architectural Highlights & Internals:
  • Blistering Analytical Performance: Vectorized query evaluation combined with SIMD instructions delivers billions of processed rows per second per server.
  • MergeTree Engine Architecture: Appends data in sorted parts and merges them in the background, utilizing primary key sparse indexes.
  • Extreme Data Compression: Specialized columnar codecs (DoubleDelta, Gorilla, T64, ZSTD, LZ4) shrink storage footprints by 70-90%.
  • Linear Distributed Scalability: Shards and replicates tables across thousands of nodes for petabyte-scale real-time telemetry and ad-tech analytics.

  • Automatic Sharding & High Availability: Replica sets provide automated failover, while sharded clusters distribute reads/writes across geographic clusters.
  • Multi-Document ACID Transactions: Guarantees consistency across multiple collections and shards without sacrificing document ergonomics.

Distributed Wide-Column / Multi-Master

Apache Cassandra

2008
Pioneered by: Avinash Lakshman & Prashant Malik (Facebook)

Apache Cassandra is a distributed, wide-column store designed to handle large amounts of data across many commodity servers, providing high availability with no single point of failure. Born at Facebook to power inbox search, Cassandra blends Amazon Dynamo's peer-to-peer ring architecture with Google Bigtable's column-family data model to achieve linear write scalability across multi-datacenter clusters.

Storage Engine:LSM-Tree (Log-Structured Merge-Tree) on SSTables
Storage Model:Wide-Column Family / Key-Partitioned
Query Interface:CQL (Cassandra Query Language)
Concurrency:Tunable Eventual Consistency (CAP AP model)
ACID & Consistency:BASE / Tunable Consistency (CAP Theorem AP: ONE, QUORUM, LOCAL_QUORUM, ALL)
P99 Latency Profile:1-5ms sub-millisecond writes at linear horizontal scale
Architectural Highlights & Internals:
  • Masterless Peer-to-Peer Ring: Every node is identical; there is no master node, eliminating single points of failure and bottleneck routers.
  • LSM-Tree Write Performance: Writes are appended sequentially to commit logs and in-memory Memtables, offering unbelievable write throughput.
  • Tunable Consistency: Developers select exact consistency levels (ONE, QUORUM, LOCAL_QUORUM, ALL) per individual read or write operation.
  • Active-Active Multi-Datacenter Replication: Replicates data synchronously or asynchronously across geographic cloud regions without downtime.

Distributed SQL (NewSQL)

CockroachDB

2015
Pioneered by: Spencer Kimball, Peter Mattis, Ben Darnell

CockroachDB is a cloud-native, distributed SQL database engineered to withstand hardware failures without human intervention—just like its namesake insect. Inspired by Google Spanner, CockroachDB offers standard PostgreSQL wire compatibility, horizontal auto-scaling, and strictly serializable ACID transactions across multi-region clusters by coordinating transactional ranges via the Raft consensus algorithm.

Storage Engine:Pebble (LSM-Tree Key-Value Engine in Go)
Storage Model:Ordered Key-Value to Relational Tables
Query Interface:PostgreSQL-Compatible SQL
Concurrency:Serializable Multi-Version Concurrency Control (MVCC) via Raft
ACID & Consistency:Strict Serializable ACID across multi-region distributed nodes
P99 Latency Profile:5-15ms globally distributed consensus transactions
Architectural Highlights & Internals:
  • Survives Node & Datacenter Outages: If a node dies, the cluster automatically rebalances and repairs data ranges without losing transactions.
  • Multi-Region Data Locality: Pin user data to specific continents/regions to comply with GDPR data sovereignty and ensure low-latency reads.
  • Raft Consensus Grouping: Data is divided into 64MB contiguous ranges, each replicated across nodes via independent Raft groups.
  • Standard PostgreSQL Wire Protocol: Works seamlessly with existing Postgres drivers, ORMs, and administrative tooling.
